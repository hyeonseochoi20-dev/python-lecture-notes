🎯 알고리즘 - 그리디 알고리즘 완전 정리

그리디 알고리즘(Greedy Algorithm)이란?

그리디 알고리즘은 매 순간 최적의 선택을 하는 알고리즘입니다.

각 단계에서 바로 앞에 있는 선택 중에서 가장 좋아 보이는 것을 선택하여 최종적인 해를 구하는 방법입니다.

그리디 알고리즘의 특징

  • 탐욕적 선택 속성(Greedy Choice Property): 각 단계에서 지역적으로 최적의 선택이 전역적으로도 최적의 해로 이어짐
  • 최적 부분 구조(Optimal Substructure): 문제의 최적 해는 그 부분 문제들의 최적 해로 구성됨
  • 일반적으로 정렬 후 순차 처리 형태로 구현됨
  • 동적 계획법에 비해 시간 복잡도가 낮음 (대부분 O(n log n) 또는 O(n))
  • 단, 모든 문제에 대해 최적 해를 보장하지 않음 (증명이 필요)

그리디 알고리즘의 일반적인 형태

정렬 또는 우선순위 결정
결과 = 초기값
for 각 요소 in 정렬된 순서:
    if 조건을 만족하면:
        결정을 내림
        결과 업데이트
최종 결과 반환

클래식 그리디 알고리즘 예시들

1. 활동 선택 문제 (Activity Selection Problem)

주어진 활동들의 시작 시간과 종료 시간이 있을 때, 서로 겹치지 않는 최대 활동 개수를 찾는 문제

def activity_selection(activities):
    # activities: [(start_time, end_time), ...] 형태의 리스트

    # 종료 시간을 기준으로 오름차순 정렬 (핵심!)
    activities.sort(key=lambda x: x[1])

    selected_activities = []
    last_end_time = 0

    for start, end in activities:
        if start >= last_end_time:  # 이전 활동이 끝난 시점과 같거나 그 이후에 시작하는 경우
            selected_activities.append((start, end))
            last_end_time = end

    return selected_activities

# 사용 예시
activities = [(1, 4), (3, 5), (0, 6), (5, 7), (3, 8), (5, 9), (6, 10), (8, 11), (8, 12), (2, 13), (12, 14)]
selected = activity_selection(activities)
print(f"선택된 활동 수: {len(selected)}")
print(f"선택된 활동: {selected}")
# 출력: 선택된 활동 수: 4
#       선택된 활동: [(1, 4), (5, 7), (8, 11), (12, 14)]

2. fractional 배낭 문제 (Fractional Knapsack Problem)

각 아이템의 무게와 가치가 주어졌을 때, 주어진 무게 제한 내에서 최대 가치를 얻는 문제 (분할 가능)

def fractional_knapsack(capacity, items):
    # items: [(weight, value), ...] 형태의 리스트
    # capacity: 배낭의 최대 무게 용량

    # 단위 무게당 가치(가치 density)를 기준으로 내림차순 정렬
    items.sort(key=lambda x: x[1]/x[0], reverse=True)

    total_value = 0
    remaining_capacity = capacity

    for weight, value in items:
        if remaining_capacity == 0:
            break

        if weight <= remaining_capacity:
            # 전체 아이템을 넣을 수 있음
            total_value += value
            remaining_capacity -= weight
        else:
            # 부분적으로만 넣을 수 있음 (분할)
            fraction = remaining_capacity / weight
            total_value += value * fraction
            break  # 배낭이 꽉 찼음

    return total_value

# 사용 예시
items = [(10, 60), (20, 100), (30, 120)]  # (무게, 가치)
capacity = 50
max_value = fractional_knapsack(capacity, items)
print(f"최대 가치: {max_value}")  # 출력: 최대 가치: 240.0
# 설명:
#   10kg 아이템 전량 (60 가치) + 20kg 아이템 전량 (100 가치) + 20kg의 30kg 아이템 (80 가치) = 240

3. 최소 동전 교환 문제 (Coin Change Problem - 그리디 버전)

주어진 동전 종류로 특정 금액을 만드는 데 필요한 최소 동전 개수 (동전 시스템이 canonical한 경우에만 최적 해 보장)

def min_coins_greedy(coins, amount):
    # coins: 동전 종류 리스트 (내림차순 정렬 필요)
    # amount: 만들고자 하는 금액

    # 큰 단위부터 사용 (그리디 선택)
    coins.sort(reverse=True)

    count = 0
    remaining = amount

    for coin in coins:
        if remaining == 0:
            break
        if coin <= remaining:
            num_coins = remaining // coin
            count += num_coins
            remaining -= num_coins * coin

    return count if remaining == 0 else -1  # -1은 만들 수 없음

# 사용 예시 (미국 동전 시스템: 1, 5, 10, 25 cent)
coins = [25, 10, 5, 1]  # 내림차순 정렬
amount = 63
min_count = min_coins_greedy(coins, amount)
print(f"{amount}원을 만드는 최소 동전 개수: {min_count}개")
# 출력: 63원을 만드는 최소 동전 개수: 6개
# 설명: 25x2 + 10x1 + 1x3 = 50+10+3 = 63 (총 6개)

# 주의: 일부 동전 시스템에서는 그리디가 최적 해를 보장하지 않음
# 예: coins = [1, 3, 4], amount = 6
# 그리디: 4+1+1 = 6 (3개)
# 최적: 3+3 = 6 (2개)

1이 될 때까지 문제 (Greedy Algorithm 예시)

이전 PDF에서 보았던 문제: N을 1로 만들기 위한 최소 연산 횟수

def min_operations_to_one(N, K):
    """
    N을 1로 만들기 위한 최소 연산 횟수
    연산 1: N에서 1 빼기
    연산 2: N이 K로 나누어 떨어지면 N을 K로 나누기
    """
    count = 0

    while N > 1:
        if N % K == 0:
            # 연산 2: K로 나누기 (더 큰 감소)
            N //= K
        else:
            # 연산 1: 1 빼기
            N -= 1
        count += 1

    return count

# 더 효율적인 버전: 한 번에 여러 번 빼기
def min_operations_to_one_optimized(N, K):
    count = 0

    while N > 1:
        if N % K == 0:
            # K로 나누기
            N //= K
            count += 1
        else:
            # K의 배수까지 한 번에 빼기
            target = N // K * K  # K의 배수 중 N보다 작거나 같은 최대값
            subtract_count = N - target
            N = target
            count += subtract_count

    return count

# 사용 예시
N, K = 25, 5
result1 = min_operations_to_one(N, K)
result2 = min_operations_to_one_optimized(N, K)
print(f"N={N}, K={K}")
print(f"기본 버전: {result1}회")
print(f"최적화 버전: {result2}회")
# 출력: N=25, K=5
#       기본 버전: 2회 (25→5→1)
#       최적화 버전: 2회

N, K = 25, 3
result1 = min_operations_to_one(N, K)
result2 = min_operations_to_one_optimized(N, K)
print(f"\nN={N}, K={K}")
print(f"기본 버전: {result1}회")
print(f"최적화 버전: {result2}회")
# 출력: N=25, K=3
#       기본 버전: 10회 (25→24→8→7→6→5→4→3→2→1)
#       최적화 버전: 10회 (동일, K=3일 때는 차이가 적음)

N, K = 1000000000, 2
result1 = min_operations_to_one(N, K)  # 매우 느림
result2 = min_operations_to_one_optimized(N, K)  # 빠름
print(f"\nN={N}, K={K}")
print(f"기본 버전: 계산 중... (약 {result1}회 연산)")
print(f"최적화 버전: {result2}회")  # 약 30회 정도

그리디 알고리즘의 적용 조건과 한계

그리디가 최적 해를 보장하는 조건

  • 탐욕적 선택 속성: 지역 최적 선택이 전역 최적 해로 이어짐
  • 최적 부분 구조: 문제의 최적 해는 부분 문제들의 최적 해로 구성됨
  • 문제의 구조가 정렬 후 순차 처리에 적합함

그리디가 실패하는 경우 예시

동전 교환 문제에서의 실패 사례

동전 종류: [1, 3, 4] (1원, 3원, 4원 동전 존재)

목표 금액: 6원

  • 그리디 해법: 큰 단위부터 사용
    • 4원 동전 1개 사용 (남은 금액: 2원)
    • 1원 동전 2개 사용
    • 총 동전 개수: 1 + 2 = 3개
  • 최적 해: 3원 동전 2개 사용
    • 총 동전 개수: 2개

이 경우 그리디가 최적 해를 보장하지 않음!

배낭 문제에서의 차이

무게 제한: 10kg

아이템 목록: (무게, 가치) = (6kg, $10), (5kg, $9), (5kg, $9)

  • 그리디 해법 (가치/무게 비율 기준):
    • 모든 아이템의 비율: 10/6≈1.67, 9/5=1.8, 9/5=1.8
    • 5kg 아이템들 먼저 선택 (비율이 더 높음)
    • 첫 번째 5kg 아이템: $9, 남은 무게: 5kg
    • 두 번째 5kg 아이템: $9, 남은 무게: 0kg
    • 총 가치: $18
  • 최적 해:
    • 6kg 아이템 ($10) + 5kg 아이템 ($9) = $19
    • 무게: 6+5=11kg > 10kg 초과 → 불가능
    • 다시 검토: 5kg + 5kg = 10kg, 가치: $9+$9=$18
    • 실제 최적: 6kg 아이템 하나만 선택 불가 (무게 초과 아님 - 6kg < 10kg)
    • 6kg 아이템 ($10) + 남은 4kg으로는 더 넣을 수 없는 아이템 없음
    • 최적은 actually: 5kg + 5kg = 10kg, $18
    • 또는 6kg alone = $10 (무게 6kg < 10kg) - 이건 더 나쁨
    • 실제 최적: 5kg + 5kg = $18

이 예시에서는 그리디가 우연히 최적 해를 찾았지만, 항상 그런 것은 아님.

그리디 알고리즘의 장점과 단점

장점

  • 구현이 비교적 간단함
  • 시간 복잡도가 일반적으로 낮음 (O(n log n) 또는 O(n))
  • 공간 복잡도가 낮음 (일반적으로 O(1) 또는 O(n))
  • 많은 실제 문제에 대해 근사해를 빠르게 제공 가능

단점

  • 모든 문제에 대해 최적 해를 보장하지 않음
  • 증명이 복잡할 수 있음 (탐욕적 선택 속성과 최적 부분 구조를 증명해야 함)
  • 문제에 따라 적절한 그리디 선택 기준을 찾는 것이 어려울 수 있음

실전 문제 해결 전략

  1. 문제 이해: 무엇을 minimization 또는 maximization 해야 하는지 명확히 하기
  2. 그리디 선택 조건 찾기: 매 단계에서 어떤 선택이 지역적으로 최적인지 결정
  3. 증명 시도: 탐욕적 선택 속성과 최적 부분 구조가 성립하는지 생각해 보기
  4. 반례 찾기 시도: 그리디가 실패할 수 있는 경우를 찾아 보기 (찾으면 다른 알고리즘 고려)
  5. 구현 및 테스트: 다양한 테스트 케이스로 검증하기

연습문제

강의실 배정 문제 (Interval Scheduling Maximization) 
# N개의 강의가 있고, 각 강의는 (시작 시간, 종료 시간)으로 표현됨
# 강의실 하나를 사용해서 최대한 많은 강의를 배정하는 문제
# (활동 선택 문제와 동일)

def max_lectures(lectures):
    # lectures: [(start_time, end_time), ...] 형태

    # 종료 시간을 기준으로 오름차순 정렬
    lectures.sort(key=lambda x: x[1])

    count = 0
    last_end_time = 0

    for start, end in lectures:
        if start >= last_end_time:  # 이전 강의가 끝났으면 배정 가능
            count += 1
            last_end_time = end

    return count

# 사용 예시
lectures = [(9, 10), (9, 11), (10, 12), (11, 12), (11, 13), (12, 14)]
max_count = max_lectures(lectures)
print(f"최대 강의 수: {max_count}")
# 가능한 배정: (9,10), (10,12), (12,14) → 3개
최대 곱 만들기 (Greedy with Sorting) 
# 주어진 숫자들을 두 그룹으로 나누어 각 그룹의 수들의 곱의 합을 최대화
# 예: [1, 2, 3, 4] → (1,4)와 (2,3) → 1*4 + 2*3 = 4 + 6 = 10
#     또는 (1,2)와 (3,4) → 1*2 + 3*4 = 2 + 12 = 14 (최적)

def max_product_sum(numbers):
    # 오름차순 정렬
    numbers.sort()

    # 작은 수와 큰 수를 짝지어 곱하는 전략
    # (두 수의 합이 고정되어 있다면 두 수가 비슷할수록 곱이 커지지만,
    #  여기서는 반대로 여러 쌍의 곱들의 "합"을 최대화하는 것이 목표이므로
    #  가장 작은 값과 가장 큰 값을 짝지어야 전체 합이 최대가 됨)

    # 실제 최적 전략: 정렬 후 교차하여 페어링
    # 가장 작은 수와 가장 큰 수를 pair, 두 번째 작은 수와 두 번째 큰 수를 pair, ...

    n = len(numbers)
    if n % 2 != 0:
        raise ValueError("짝수 개수의 숫자가 필요합니다")

    total = 0
    left = 0
    right = n - 1

    while left < right:
        product = numbers[left] * numbers[right]
        total += product
        left += 1
        right -= 1

    return total

# 사용 예시
numbers = [1, 2, 3, 4]
result = max_product_sum(numbers)
print(f"숫자들: {numbers}")
print(f"최대 곱의 합: {result}")
# 페어링: (1,4) → 4, (2,3) → 6, 총합: 10
# 다른 페어링: (1,2) → 2, (3,4) → 12, 총합: 14
# 실제 최적은 (1,4)와 (2,3)인가? Let me recalculate...
# Actually for [1,2,3,4]:
# Option 1: (1,4)+(2,3)=4+6=10
# Option 2: (1,2)+(3,4)=2+12=14 ← 이것이 더 큼
# Option 3: (1,3)+(2,4)=3+8=11
# 따라서 정렬 후 양 끝에서 inward로 페어링이 아닌,
# 연속된 쌍으로 페어링이 더 나을 수 있음

# 올바른 접근: 정렬 후 인접한 요소들을 페어링
def max_product_sum_corrected(numbers):
    numbers.sort()
    total = 0
    for i in range(0, len(numbers), 2):
        total += numbers[i] * numbers[i+1]
    return total

result_corrected = max_product_sum_corrected(numbers)
print(f"수정된 버전 결과: {result_corrected}")  # 1*2 + 3*4 = 2 + 12 = 14
